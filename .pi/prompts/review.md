# Review

Target:
$ARGUMENTS

Review the relevant code before making any changes.

Evaluate:

1. Correctness
2. Readability
3. Maintainability
4. Architecture and separation of concerns
5. Error handling
6. Tests and test coverage
7. Security risks
8. Unnecessary complexity
9. Duplication
10. Likely failure modes

For each important issue:

- Explain what is wrong
- Explain why it matters
- Point to the relevant file or code area
- Suggest a better approach

Prioritize findings by impact.

Do not modify files unless explicitly asked.
